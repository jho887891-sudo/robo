# R24 — 训练不足假设验证与收敛实验

基线 `feature/r15-true-continuation@f34cc44`，本分支 `research/r24-training-convergence-audit`。
独立审计 PR#30 已在执行前核对，其指出的 SAFE 对比口径缺陷是 Stage B 的起点。

---

## 0. 结论先行（不是只凭 Training Loss）

**现有证据最支持 H4（动作表征 / 残差不可学），H2（学习率）是加重因素，H3（泛化恶化）被证伪，H1（训练不足）是事实但不是当前瓶颈。**

一句话：**在相同的 SAFE 解码与裁剪下，共享模型的物理动作误差与"保持当前速度"这个零参数基线在统计上无法区分；而残差本身在给定状态下几乎不可预测，所以再多训练步也无法击败它。**

| 假设 | 判定 | 决定性证据 |
|---|---|---|
| H1 训练样本覆盖不足 | **部分成立，但不是瓶颈** | 只有 0.033 epoch（2000 步 / 61,171 帧）；但模型连**训练帧**都没有拟合（train CE 1.90 vs dev 1.95），说明增加覆盖不会改变结论 |
| H2 学习率/衰减不当 | **加重因素（实证）** | R15 的 `lr_milestone` 默认 = 1000，而 R15 正好只跑 1000 步 → **衰减只在最后一步触发**，整个血缘在 peak LR 5e-4 下完成 |
| H3 Loss 降但泛化恶化 | **证伪** | 训练帧与 DEV 帧误差几乎相同（见 §3）；没有任何过拟合特征 |
| H4 表征/解码/安全使 Loss 改善无法转为动作 | **最受支持** | 零残差（= CV）是**所有候选预测器中最好的**；线性探针 R² = **−19.95 / −8.72**；模型在全部 6 个分层上发出的运动量 ≈ CV |

**追加训练是否值得？用同一配方不值得。** 详见 §6。

### 1.5 学习率：一个真实的配置错误

```
R15  training/r11_train_pushT_r42.py:456   MultiStepLR(milestones=[max(1, args.lr_milestone)], gamma=0.1)
     :1044  --lr_milestone 默认 1000
M2   training/m2_train_shared.py:1003      MultiStepLR(milestones=[...args.milestones], gamma=0.1)
     :1221  --milestones 默认 "1000,2500"
```

| run | 计划衰减点 | 实际发生 | 结果 |
|---|---|---|---|
| R15 (0→1000) | 1000 | 在 **step 1000**，即最后一步 | **整条血缘都在 5e-4 峰值学习率下训练，衰减从未生效** |
| M2 (0→2000) | 1000, 2500 | 1000 | 前 1000 步 5e-4，后 1000 步 5e-5；2500 处的衰减从未到达 |

这是 H2 的硬证据：R15 的"300→1000 恶化"完全发生在**常数高学习率**区间内，一个从未执行的衰减策略不可能救它。

## 2. Stage B：先修正评测口径（审计 PR#30 的缺陷是真的）

### 2.1 修正了什么

| 缺陷 | v1（R17） | v2（本报告） |
|---|---|---|
| 裁剪 | 只对模型 clip，基线**不裁剪** | **三者全部**经 `r42_adapter.decode_command` |
| 量化 | 模型走 256-bin codec，基线是实数 | 三者都走同一 codec |
| 夹爪回退 | 谁都没做 | 三者都应用 `cmd[6]=cmd[13]=S+V` |
| 泛化 | 单一 8 帧集合 | 冻结的 284 帧分层清单 |

v2 没有任何重实现可漂移：三条策略调用**同一个** `decode_command`，只有残差不同
（model = codec 逆映射；CV = 0；no-op = −V）。新旧两版并存，v1 原样保留。

顺带记录两处 v1 的自身缺陷（都已在本轮修掉，且不掩盖）：
1. v1 把 `decode_command` 的返回值 `(cmd, r_hat, info)` 误当成 `(raw, safe, info)`，等于拿**残差**当 SAFE 命令去比动作，会让所有策略都显示 L1≈0.38。已修正并注释。
2. `tools/r24_frame_manifest.py` 首版用 `t>=1`，而训练契约要求 `t>=2`（`[S,V,Acc]` 需要两个历史帧）。该版清单在**任何模型运行之前**被拒绝并重新冻结，旧版保留为 `frame_manifest_v1_REJECTED.json`。

### 2.4 关键判据：模型能否拟合**它训练过的帧**？

同一个 step2000 checkpoint、同一代码路径，分别在 TRAIN 帧与 DEV 帧上测（`tools/r24_fit_test.py`，纯推理，**零优化步**）：

| task | TRAIN ce_window | DEV ce_window | 差 |
|---|---|---|---|
| push_T | 1.8983 | 1.9476 | train 好 2.6% |
| stack_bowls | 2.2372 | 1.9456 | **train 差 15.0%** |

| task | TRAIN SAFE L1 | DEV SAFE L1 |
|---|---|---|
| push_T | 0.00628 | 0.01033 |
| stack_bowls | 0.01043 | 0.00249 |

过拟合的签名是 train ≪ dev。这里**两个任务都没有**；stack_bowls 的 train 甚至更差。
**H3（泛化恶化 / 记忆）被证伪。**

### 2.5 残差可学性：为什么模型无法超过 CV

`tools/r24_learnability.py`，只用冻结清单，TRAIN 拟合 / DEV 评估：

| task | 线性探针 DEV R² | 零残差 SAFE L1 | 训练均值残差 SAFE L1 | 线性探针 SAFE L1 |
|---|---|---|---|---|
| push_T | **−19.95** | **0.010287** | 0.010510 | 0.015582 |
| stack_bowls | **−8.72** | **0.002339** | 0.002471 | 0.004036 |

要从 (S, V) 预测残差，线性探针 R² = **−19.95**：比"直接预测均值"还差得多。
而**零残差（= 恒速命令）是这三个里最好的**。

结构原因：`R_t = (A_t − S_t) − V_t` 的**条件均值≈0**（|mean R| = 0.00052 vs |R| = 0.00261，20%），
所以 L2/L1 最优预测就是"接近 0"，而 0 恰好就是 CV 基线。**这正是 CV 如此难打败的原因，也是数据集本身的属性，不是训练缺陷。**

| fast_motion | 12 | 0.02738 | 0.02742 | 0.03108 | 0.03115 | 0.00070 |

## 3. 为什么 H1 成立却不是瓶颈

H1 的事实成立（0.033 epoch）。但把它当作瓶颈需要满足一个前提：**模型能把训练数据拟合好，只是没见过足够多**。
2.4 直接否证了这个前提——train 与 dev 一样差，甚至更差。在**没有过拟合**且**训练误差仍然很高**时，增加数据量只能让 loss 缓慢下降而不会改变映射能力；而 2.5 说明真正限制映射能力的是目标本身近乎不可预测。

因此：H1 描述的是**现状**，H4 描述的是**上限**。

完整协议见 `mission/r24/continuation_prereg.md`。要点：

* 起点：`m2_two_2000_20261021T123314Z/checkpoints/step2000`（保留，绝不覆盖）
* **A 臂（真正续训对照）**：严格恢复 optimizer + scheduler + sampler + RNG；scheduler 的 milestones 必须沿用原始 `1000,2500`（因此 A 臂在 2000→2500 仍处于 5e-5）

* 首轮申请上限：**+6000 有效优化步**（至 global 8000），主 Gate 在 **4000** 与 **8000**
* A/B 先导实验的消耗**另计**并单独列账，不得从 6000 里挪用
* 每个 Gate 必须同时满足：DEV CE 不升、**同口径 SAFE L1 相对 CV 的配对 CI 上界 < 0**、无夹爪退化、无坍缩
* 立即停止条件：DEV 连续恶化、动作坍缩、非有限 loss、梯度异常、接口不一致
* **若 CE 继续下降而 SAFE L1 对 CV 仍不可区分 → 停止加步数**，转入动作表征诊断（即本轮 H4 路线）

**预算是 0 步**：本报告没有启动任何优化步。

## 6. 直接回答"追加训练是否值得"

**用同一配方：不值得。** 依据不是 loss，而是三条独立证据：

1. 模型连训练帧都没拟合（train ≈ dev，stack_bowls 甚至更差）→ 不是"见得少"，是"学不动"；
2. 目标残差的条件均值≈0，零残差就是最优 → 任何改进都必须来自"预测出非零残差"，而线性探针 R² = −20 说明这个信号在 (S,V) 里几乎不存在；
3. 公平对比下模型与 CV 统计不可区分，而 CV 在闭环里也失败 → 即使把 loss 压到 0，物理行为也不会自动变成"会推"。

**值得做的方向**（需负责人决策，本轮未启动）：
* **换监督目标**：现在的目标是"下一步残差"，它把可学信号压到了噪声量级。改用**多步动作块（action chunking）**或**任务进度/子目标**作为监督，目标的条件均值不再≈0。
* **换评测口径**：离线 1-step L1 已被证明会偏好"不能起动"的策略（CV 离线最好、闭环最差）。后续 Gate 必须以**闭环物体位移**为主指标。
* **若仍要走纯行为克隆**：至少需要 DAgger 式闭环纠错数据，而不是更多同分布示范。
