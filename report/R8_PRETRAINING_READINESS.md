## 0. 摘要（中文）

1. **数据量是决定性因素（已验证，严格匹配消融）**：固定 64 训练回合 / 16 开发回合 / 20 留出回合、
   固定 `[S,V,Acc]`、固定 R 目标、固定网络与优化器、3 个种子，只改变**训练帧数**：
   200 帧 → 0.0137–0.0448（比恒速差 7.6–24.9 倍，比 identity 还差）；
   2,000 帧 → 0.0025–0.0053（仍比恒速差 1.4–3.0 倍，R² 为负）；
   全量 19,127 帧 → **0.001186–0.001246（比恒速好 31–34%，R² 0.51–0.54，20/20 回合胜）**。
   三种协议（相同更新次数、相同遍历轮数、DEV 选择）**给出同一排序**。
2. **200 帧确实不足以学习速度修正量（已验证）**：最优 200 帧结果 0.013676（8,000 步），
   方向余弦 0.569、R² −18.5、符号 0.559（≈随机），20 个留出回合 **0 胜**。
3. **2,000 帧"部分可用但不过关"（已验证）**：方向余弦升到 0.939（相同更新次数），
   但 R² 仍为 −0.21、L1 仍为恒速的 1.40 倍 ⇒ **方向学到了一部分，幅度/总体误差仍不如恒速**。
4. **2,000 → 全量继续显著改善（已验证）**：相同 8,000 步下 L1 0.002506 → 0.001246（×2.0），
   R² −0.209 → +0.511，符号 0.770 → 0.828，胜回合 0 → 20/20。
5. **R 目标 vs Δ 目标（修正后）**：R 略好但幅度很小 —— L1 0.001727 vs 0.001787（3.4%）、
   R² 0.311 vs 0.301。**"R 目标是关键"不成立；它是小幅、可解释、且便于部署回退的改进。**
6. **R8 契约已具备（CPU 可验证部分全部通过）**：42 维 `[S,V,Acc]`、速度残差目标、边界帧规则、
   训练/部署时间对齐、train-only 分位、元数据 fail-closed、旧检查点兼容，27 项契约测试 + 真实 HDF5
   最小批次测试全部通过。**唯一未验证项**：42 维投影层 + KV-cache 自回归的真实 GPU 前向（已准备
   smoke 命令，本轮未运行）。
7. **可以进入小规模 GPU 实验**，但门槛与预算必须按 §6 的形式写入下一轮；**不建议**直接上
   3000/6000 步。

### 1.4 必须回答的五个问题

**Q1：200 帧是否真的不足以学习速度修正量？** **是（已验证）。** 最优 200 帧配置 0.013676
比恒速差 7.6 倍、比 identity（0.007015）还差 1.9 倍；R² 为 −18.45、R 符号 0.559、20 回合 0 胜。
增加步数（8,000 步 = 8,000 轮）只是让它**过拟合**：L1 反而比 400 轮时更接近恒速，但 R² 更差。

**Q2：200 → 2,000 是否明显提高方向准确率？** **是（已验证）。** 相同 8,000 步下：
Δ 余弦 0.569 → 0.939、R 符号 0.559 → 0.770、R 相关 0.067 → 0.491。
但 **L1 仍为恒速的 1.40 倍、R² 仍为 −0.21** ⇒ 方向改善不等于总体误差达标。

**Q3：2,000 → 全量是否继续改善？** **是，而且这是最大的一跳（已验证）。** 相同 8,000 步下
L1 0.002506 → 0.001246（×2.0），R² −0.209 → +0.511，R 符号 0.770 → 0.828，胜回合 0 → 20/20。
数据量在这一段跨过了"能超过恒速"的门槛。

**Q4：数据量与更新次数各自的影响？**
* 固定更新次数（8,000 步）：200 → 2,000 → 全量 = 0.013676 → 0.002506 → 0.001246
  （**5.5× 然后 2.0×**，全部由数据量带来）。
* 固定遍历轮数（200 轮）：0.044771 → 0.005336 → 0.001242（**8.4× 然后 4.3×**）。
* 固定数据量，只加更新：2,000 帧 800 → 8,000 步 = 0.005336 → 0.002506（2.1×）；
  全量 8,000 步 vs 13k 步 = 0.001246 vs 0.001186（5%）。
⇒ **在 2,000 帧这一档，增加步数可以部分弥补数据；到 2,000 帧上限附近仍明显劣于全量，
而在全量数据上 8,000 步已经接近饱和。**

**Q5：模型是真的学会了预测速度变化，还是只会输出零修正？**
**真学会了（已验证）。** 全量数据：R² **0.536**（相对于"零修正"的方差解释）、
R 相关 **0.732**、R 符号 **0.833**、Δ 余弦 **0.958**、`|Δ|≥1e-3` 符号 **0.973**，
20/20 回合配对改善（均值 −0.000587，最差回合仍改善 −0.000345）。
如果只是输出零修正，R² 会是 0，L1 会等于恒速 0.001795。

## 2. 第三阶段：R8 契约（42 维历史 proprio + 速度残差目标）

模块：`code/xpolicylab/policy/OpenVLA_Pure/r8_contract.py`（numpy only，不触碰 R2–R7 代码）。

### 2.1 定义与边界规则

```
P_t   = [S_t, V_t, Acc_t]                        (42 = 14 + 14 + 14)
V_t   = S_t − S_(t−1)                             t ≥ 1 ；t = 0 时 V = 0
Acc_t = S_t − 2·S_(t−1) + S_(t−2)                 t ≥ 2 ；t = 0,1 时 Acc = 0
训练监督  R_t = (A_t − S_t) − V_t
推理命令  Â_t = S_t + V_t + R̂_t
```

* 边界规则在**训练、验证、部署**三处使用同一实现（`build_proprio` / `HistoryBuffer`），
  并有测试断言三者对同一观测序列产生**逐位相同**的 42 维向量；
* 部署端只缓存**最近两个已观测状态**，绝不把预测回灌历史；
* 分位 `velocity_residual_quantiles` 只在**训练回合**的 R 表示上计算（≥100 行才允许）；
* 256-bin 编码器本身**未修改**（R2 冻结的 fixed codec），解码后按 `S + V + R̂` 还原物理命令。

### 2.2 检查点元数据（fail-closed）

R8 检查点必须声明 `proprio_mode="svacc"`、`proprio_dim=42`、
`target_representation="velocity_residual"`、14 维 `q01/q99`；缺任何一项即拒绝加载。
旧检查点（无 `proprio_mode`）按 14 维（R2–R5）或 28 维（R6）解析，语义不受影响；
投影层宽度与声明不符时在 `load_state_dict` 之前报错。

### 2.3 集成检查清单（R8 是否已具备训练/推理契约）

| 项 | 状态 |
|---|---|
| 数据加载器输出 (t, t−1, t−2) 与边界规则 | **已实现 + 已测试** |
| 42 维 ProprioProjector | 宽度契约已实现并测试；**权重尚未训练** |

## 4. 测试集重复使用的限制

R2–R8 的所有结论都基于同一组 20 个留出回合；本轮又在其上比较了 9 种（规模×协议）配置 ×
3 个种子，以及 R7 的 6 种特征/目标组合。因此该留出集已经被**反复使用**：

* 存在隐式选择偏差，任何"刚好通过"的差距都应打折看待；
* 本文所有比值（如 0.661× 恒速）应视为**该批帧上的离线测量**；
* **下一步必须先划出全新独立评测集**（例如从未参与调参的新采集 push_T 回合，或按回合划分的
  第二套 holdout），在看到结果前冻结模型、超参与阈值；
* 在独立集上复现"20/20 回合、R²>0.3、方向符号>0.75"之前，不应把本结果当作可交付能力。

## 5. 下一步建议（明确、可执行）

1. **优先投入"数据覆盖"，而不是训练步数**：全量 19,127 帧在 8,000 步即饱和；2,000 帧即使
   8,000 步仍不如恒速。若要把 7B 微调跑出意义，最小规模应是"全部训练帧流式读取"，
   而不是 200/2,000 帧缓存。
2. **三帧历史（Acc）是最大且最稳的收益**：同一批帧上 `[S,V,Acc]` 比 `[S,V]` 好
   0.001204 vs 0.001696（−29%），比恒速好 32.9%，20/20 回合。**建议 R8 直接采用 42 维。**
3. **R 目标可以引入，但要按"小幅改进 + 部署可用性"定位**：L1 只比 Δ 好 3.4%，
   R² 0.311 vs 0.301。它的真正价值是：目标与"零修正"基线同尺度、便于早停/回退，
   并且部署时显式需要 V（我们本来就有）。
4. **夹爪通道用 DEV 规则固定为恒速**（12 个手臂维用模型），避免右夹爪退化。
5. **GPU 实验前必须先过 42 维 smoke**（前向/反向、投影层梯度、slot 敏感性、KV==全序列、
   无未来泄漏），本轮的 CPU 契约只能覆盖到"接口正确"，不能替代这一步。
6. **预注册下轮的 GPU 预算与门槛**：建议 ≥10k 不同训练帧流式、LoRA+42 维投影层、
   目标 R、夹爪恒速通道；验收门槛沿用 §3 的 8 条，并在**新的独立留出集**上评测。
